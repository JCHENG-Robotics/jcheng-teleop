## 1. Storage-failure drill

`PYTHONPATH=src python3 tools/disk_full_drill.py`

`RLIMIT_FSIZE` is lowered to 512 bytes with `SIGXFSZ` ignored, so writes fail
with EFBIG (the same error path as a full disk). The drill requires the
recorder to fault, the session to stop and the capture to be sealed with a
fault label. A storage fault can truncate the row being written, so the package
may verify `invalid`; it is retained for diagnosis and is not exportable.


The drill uses `queue_limit=65536`: it produces rows faster than real time, and
the default 4096 buffer is sized for a 50 Hz live producer. With the default
queue the same run drops rows and every episode is `degraded`; that is the
intended bounded-memory behaviour, not a valid acceptance run.
